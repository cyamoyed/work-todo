# WorkTodo 开发计划

> 版本：v1.0 · 编制日期：2026-10-09 · 状态：**已实施（Phase 1–5 全部交付）**
> 输入：产品分析（用户视角）结论 · 范围：下阶段功能与体验优化
> 实施结果：见文末「交付记录」。

---

## 1. 背景与目标

WorkTodo 已交付 MVP（任务 CRUD、状态/优先级、筛选搜索、逾期标识、删除撤销、Tauri 脚手架），测试 411 项全绿。产品分析指出的核心矛盾是：

- **信任不足**：数据只存 `localStorage`，工作用户不敢托付真实任务；
- **上下文缺失**：只有标题，隔天打开不知道任务要做什么；
- **「今日」承诺落空**：主视觉「今日推进」统计的是全量数据，且无「今天/本周」视图；
- **细节矛盾**：删除文案与撤销能力打架，确认框焦点落在危险按钮上；
- **高频操作慢**：无快速添加、无批量清理、排序固定、逾期无外推。

**本计划目标**：在不破坏现有「轻量、单人、台账」定位的前提下，按优先级消除上述摩擦，形成 v0.2 交付。

**成功标准（v0.2）**：

1. 用户可在 10 秒内导出/导入全量任务数据；
2. 每条任务可附带备注，且备注可被搜索命中；
3. 打开应用能立刻回答「今天该干什么」；
4. 删除/焦点/文案等信任细节与真实行为一致；
5. 回归测试不少于现有 411 项，新增场景全部覆盖。

## 3. 规划原则

1. **信任优先于功能**：数据安全 > 上下文完整性 > 今日视图 > 效率增强。
2. **不扩大产品面**：不做云同步、账号、看板、子任务、重复任务、多语言（见 §7）。
3. **可回滚**：每阶段独立可交付、可验收，不引入破坏性数据迁移（迁移需兼容 `worktodo.tasks.v1`）。
4. **测试同权**：新能力必须带自动化用例；改交互必须补 Playwright 冒烟。

## 4. 分阶段实施

### Phase 1 — 数据安全与信任（P-01 / P-02 / P-07 / P-08）

**目标**：用户敢把真实工作放进来了。

| 任务 | 内容 | 验收标准 | 覆盖问题 |
|------|------|----------|----------|
| T1.1 导出 JSON | 设置入口（顶栏「⋯」或页脚）→ 导出 `worktodo-YYYYMMDD.json` | 导出文件含全部字段，`JSON.parse` 可还原；文件名含日期 | P-01 |
| T1.2 导入 JSON | 选择文件 → 校验 → 确认合并/覆盖 → 成功/失败 Toast | 非法 JSON、字段缺失、版本不符有明确错误；导入后刷新不丢 | P-01 |
| T1.3 数据版本 | 文件头写入 `{ schemaVersion, exportedAt, tasks }`；读取兼容 v1 | 旧数据可导入；未来可升级 | P-01 |
| T1.4 桌面持久化 | Tauri 侧改用应用数据目录文件（或 SQLite）存储；启动时若存在 localStorage 则一次性迁移 | 桌面版与浏览器版数据分离且各自可导出；迁移不重复导入 | P-02 |
| T1.5 删除文案 | 「删除后无法恢复」→「删除后可短暂撤销」 | 文案与 Toast 行为一致 | P-07 |
| T1.6 确认焦点 | 焦点默认给「取消」；Tab 顺序合理 | Playwright 断言 `document.activeElement` | P-08 |

**预计工作量**：3–4 天（含桌面持久化联调）。

**技术要点**：

- 导出/导入沿用现有纯前端实现，`Blob` + `a[download]` / `<input type="file">`，无新依赖。
- 导入策略默认「合并」（按 `id` 去重，同 id 取 `updatedAt` 较新者），覆盖作为二次确认选项。
- 桌面端存储：`tauri-plugin-fs` 或 `tauri-plugin-store`，路径 `app_data_dir/tasks.json`；导出/导入与 Web 共用同一套序列化逻辑。

### Phase 2 — 任务上下文与搜索（P-03 / P-04）

**目标**：任务能自解释，隔天还能接着做。

| 任务 | 内容 | 验收标准 | 覆盖问题 |
|------|------|----------|----------|
| T2.1 数据模型 | `Task` 增加 `notes: string`（可选，0–2000 字符，纯文本） | `createTask`/`updateTask` 支持；`isValidTask` 兼容旧数据（缺省 `''`） | P-03 |
| T2.2 表单 | 新建/编辑弹窗增加「备注」多行输入 | 保存后编辑可回填；超长有校验 | P-03 |
| T2.3 列表呈现 | 卡片标题下显示备注摘要（1 行，超过省略号）；无备注不占位 | 已完成弱化样式不被破坏 | P-03 |
| T2.4 搜索扩展 | `visibleTasks` 对 `title + notes` 做大小写不敏感子串匹配 | 备注关键词可命中；与筛选仍为 AND | P-04 |
| T2.5 XSS 防护 | 备注一律 `textContent` 渲染，禁止 `innerHTML` | 现有 `unit-security` 套件补备注注入用例 | P-03 |

**预计工作量**：2 天。

**数据迁移**：`loadTasks` 读旧数据时 `notes = notes ?? ''`，写回不强制升级版本号（保持 `worktodo.tasks.v1`，schema 向后兼容）。

---

### Phase 3 — 今日视图与概览口径（P-05 / P-06）

**目标**：打开应用 3 秒内知道今天该干什么。

| 任务 | 内容 | 验收标准 | 覆盖问题 |
|------|------|----------|----------|
| T3.1 概览口径 | 改为「今日」语义：今日到期、今日逾期、今日完成、进行中 | 文案与数字一致；副文案不再用全量口径 | P-05 |
| T3.2 今日筛选 | 筛选条增加「今天」「本周」chip（与状态/优先级可组合） | 命中 `dueDate` 落在今天/本周（周一为一周起点）；无截止日不进入今日 | P-06 |
| T3.3 空态 | 今日视图无任务时引导「添加今天要做的事」 | 与现有空态风格统一 | P-06 |
| T3.4 排序微调 | 今日视图内：逾期 → 今天到期 → 今天已完成（弱化） | Playwright 断言顺序 | P-06 |

**预计工作量**：2 天。

**口径定义**（避免再歧义）：

- **今日到期**：`dueDate == today && status != 'done'`
- **今日逾期**：`dueDate < today && status != 'done'`
- **今日完成**：`status == 'done' && updatedAt` 落在今天（近似；若后续有 `completedAt` 再切换）
- **本周**：`dueDate` ∈ [本周一, 本周日] 且 `status != 'done'`

### Phase 4 — 效率与感知（P-09 ~ P-13）

**目标**：高频动作从「多点几下」变成「顺手完成」。

| 任务 | 内容 | 验收标准 | 覆盖问题 |
|------|------|----------|----------|
| T4.1 快速添加 | 弹窗支持「标题 + Enter」直接保存，其余字段默认值；或列表顶部内联输入框 | 两步内完成记一笔；Esc 取消 | P-09 |
| T4.2 清除已完成 | 列表操作「清除已完成」→ 确认 → 一次性删除 + 单条 Toast 撤销（整批快照） | 撤销可恢复全部；无已完成时入口隐藏/禁用 | P-10 |
| T4.3 排序切换 | 列表头提供「截止日（默认）/ 优先级 / 创建时间」 | 切换即时生效并记忆（session 级即可） | P-11 |
| T4.4 已完成折叠 | 默认折叠已完成（显示「已完成 N 项 · 展开」） | 状态筛选=已完成时自动展开 | P-13 |
| T4.5 桌面通知 | 桌面端启动或每日首次打开时，对逾期任务发系统通知 | 仅桌面端生效；Web 端静默降级 | P-12 |

**预计工作量**：3–4 天。

## 6. 技术与质量约束

1. **架构不变**：继续纯 HTML/CSS/JS，无打包器、无运行时 npm 依赖；Tauri 仅作壳。
2. **数据兼容**：`worktodo.tasks.v1` 只增字段不删不改类型；导入接受 v1 与 `schemaVersion: 2`（若引入）。
3. **安全**：所有用户输入（尤其 `notes`）走 `textContent`；导入文件必须 `JSON.parse` 后逐字段校验（复用 `isValidTask`）。
4. **可访问性**：新控件补 `aria-label` / `aria-expanded`；焦点陷阱沿用现有 modal 模式；删除确认焦点给「取消」。
5. **测试**：
   - 逻辑层：`notes` 校验、导入合并策略、今日/本周日期边界（含跨年、周一起点）；
   - 安全层：备注 XSS、导入恶意 JSON；
   - E2E：导出下载 → 导入回读；今日筛选命中；快速添加；批量撤销。
   - 现有 `tests/run-all.js` 全量保持绿。
6. **性能**：任务量按 ≤ 500 条设计；列表渲染保持一次 `render()`，不做虚拟列表（暂不需要）。

## 7. 明确不做（本阶段非目标）

- 账号体系、云同步、多设备冲突合并
- 子任务、标签、附件、看板、日历视图
- 提醒重复任务、GTD 项目/上下文体系
- 国际化、暗色主题切换
- 移动端原生 App

若以上某项在评审时升级为必须，需重新评估里程碑，不得直接塞进当前阶段。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 桌面持久化迁移重复/丢失 | 用户数据 | 迁移后写标记 `migratedAt`；保留 localStorage 原数据不删，直到首次成功导出 |
| 导入合并策略不符合预期 | 覆盖用户数据 | 默认合并 + 明确确认文案；覆盖模式二次确认；导入前自动本地快照 |
| 「今日完成」用 `updatedAt` 近似 | 口径仍可能偏差 | v0.2 允许近似并在 UI 不暴露精确名；v0.3 增加 `completedAt` 字段 |
| T5.2 时间点影响排序/逾期比较 | 逻辑回归 | 单独排期，先补日期边界测试再动比较器 |
| 窗口窄屏改版引发桌面布局回退 | 视觉回归 | 以 Playwright 截图对比桌面 1280 / 移动 375 双基线 |

## 9. 验收与发布

1. **功能验收**：按各 Phase 验收标准逐条勾选；Playwright 走通「导出 → 清空 → 导入 → 恢复」全链路。
2. **回归**：`node tests/run-all.js` 全绿（不少于 411 项，预计新增 80+）。
3. **视觉**：桌面/移动双端截图走查，确认主视觉与任务卡片无回归。
4. **打包**：`npm` 侧 `prepare-dist.js` 产出 `dist/`；Windows 桌面包更新 `release/` 说明与版本号至 0.2.0。
5. **文档**：更新 `docs/BUILD.md`（导出/导入路径、桌面数据目录）与本计划勾选状态。
