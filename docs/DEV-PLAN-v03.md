# WorkTodo v0.3 开发计划

> 版本：v0.3 · 编制日期：2026-10-09 · 状态：**已交付**
> 输入：产品体验审计（界面交互 / 操作体验 / 场景完备性）
> 目标：消除语义误导与视图失步，补齐移动端与工作场景缺口，形成可信的个人工作台账。

---

## 1. 背景

v0.2 已交付信任与效率能力（导出导入、备注、今日口径、快加、折叠、通知），500 项测试全绿。
本轮审计发现：产品骨架健康，但存在 **3 处误导判断的语义/视图问题**、**移动端能力缺口**，以及从「台账」到「日常工作工具」的功能层缺口。

**成功标准（v0.3）**

1. 同一语义词全站只有一种口径（「进行中 / 待推进」）；
2. 侧栏高亮与列表内容始终一致；
3. 日程分组名称与真实日期范围一致；
4. 移动端可切换视图并导出数据；
5. 删除/清空可撤销窗口足够长，批量删除可恢复；
6. 具备到期提醒、重复任务、本周回顾；
7. 回归测试不少于 500 项，新场景全部覆盖。

## 3. 规划原则

1. **语义一致优先**：同一词全站一种含义；文案跟统计口径绑定。
2. **单一状态源**：视图/筛选只保留一处权威状态，UI 控件全部同步自它。
3. **向后兼容**：`worktodo.tasks.v1` 只增字段不删不改；旧数据可读可导。
4. **可恢复**：所有破坏性操作有足够长的撤销或快照恢复。
5. **测试同权**：每条变更带自动化用例；交互变更补 DOM/E2E 断言。

## 4. 分阶段实施

### Phase 1 — 语义与视图一致性（A-01 / A-02 / A-03 / A-04 / A-05 / A-06 / A-13）

| T1.5 completedAt | `Task` 增加 `completedAt: string\|null`；置为 done 时写入，改回未完成时清空；「今日完成」改用 `completedAt` | 旧数据兼容；编辑备注不改变今日完成 |
| T1.6 创建反馈 | 新建落在当前视图外时 Toast 说明并自动展开到可见范围，或保留视图并提示「已创建，在全部中查看」 | 用户不丢失上下文 |
| T1.7 字段扩展 | 增加 `repeat: null\|'daily'\|'weekly'\|'monthly'\|'weekday'` 与 `tags: string[]`（≤5 个，每个 ≤12 字） | 导入导出含新字段 |

## 5. 技术要点

- 数据迁移：`normalizeTask` 补默认 `completedAt: null, repeat: null, tags: []`；`isValidTask` 不强制新字段。
- 视图状态：`setView(view)` 统一写 `viewMode` + `filters.range` + `filters.status`，所有入口调用它。
- 日程分组使用 `weekRange()` / `dayDiff()` 真实周界，不用固定标题装未来。
- 通知防抖：同一任务同一日只提醒一次（`notifiedAt` 内存/ localStorage key）。
- 重复生成：`cloneNextOccurrence(task)` 仅在用户确认或启动扫描时执行，避免静默造数。

---

## 6. 风险

| 风险 | 对策 |
|------|------|
| 视图状态重构破坏现有筛选组合 | 先补 E2E 断言再改；`filters` 对象字段保留 |
| 重复任务造成任务爆炸 | 仅生成下一期 1 条；无无限滚动生成 |
| 通知打扰 | 合并逾期一条 + 到期前 60 分钟一次 |
| 测试基线被文案改动打穿 | 先改测试期望再改产品文案 |
